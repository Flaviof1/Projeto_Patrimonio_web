Importante: o aplicativo não tem login próprio. Quem consegue abrir o endereço do sistema pode consultar, editar, importar, gerar e baixar dados. Para acesso remoto, mantenha a rede Tailscale restrita a dispositivos e pessoas de confiança. Nunca encaminhe a porta do app no roteador.

1. Visão geral

O sistema organiza a conferência patrimonial por setor. A tela inicial apresenta a situação da base: origem ativa (MySQL ou planilha), total de bens, setores, quantidade por status, data da última preparação, fontes importadas e disponibilidade das fotos.

No ambiente atual, o MySQL local do PC servidor é a fonte ativa. As planilhas de conferência são mantidas como espelhos para compatibilidade e recuperação. Os outros aparelhos acessam o Flask pelo navegador; não se conectam diretamente ao MySQL.

2. Como acessar

No próprio computador

Abra http://127.0.0.1:8765.

Na mesma rede Wi-Fi ou cabeada

Use o endereço IPv4 do PC servidor, mostrado no terminal ao iniciar o Flask, seguido de :8765. Exemplo: http://192.168.1.20:8765. Os aparelhos precisam estar na mesma rede e o firewall do Windows pode solicitar autorização para rede privada.

De outra rede usando Tailscale

  1. Instale o aplicativo oficial do Tailscale no PC servidor e no aparelho de auditoria e entre na mesma rede/conta Tailscale.
  2. No painel Máquinas do Tailscale, confirme que PC e aparelho aparecem conectados.
  3. Copie o endereço Tailscale do PC servidor (um IPv4 que normalmente começa com 100.), não o endereço do iPhone.
  4. Com Tailscale conectado no iPhone, abra no Safari http://IP-DO-PC:8765. O endereço verificado neste PC em 22/10/2026 era http://100.85.183.31:8765. O IP do Tailscale normalmente permanece o mesmo depois de desligar e ligar o PC.

O PC deve permanecer ligado e sem suspensão. MySQL e Flask também devem continuar ativos. Não é necessário abrir ou encaminhar a porta no roteador. Para encerrar o Flask, volte ao terminal do servidor e pressione Ctrl+C.

O endereço pode mudar se o PC for removido da rede Tailscale e adicionado novamente, se o Tailscale for redefinido/reinstalado e perder o registro do dispositivo, se o disco for apagado ou se um administrador mudar o IP manualmente. Se não conectar, confira o endereço do PC em Máquinas no painel Tailscale.

3. Passo a passo: ligar o sistema depois de reiniciar o PC

Há duas coisas diferentes: o endereço Tailscale do PC normalmente continua o mesmo; o programa Flask precisa ser iniciado novamente depois que o Windows reinicia. Faça estes passos no PC servidor sempre que quiser usar o sistema. O VS Code não é obrigatório: ele é apenas um editor que também oferece uma janela de terminal. Você pode iniciar o servidor pelo terminal do VS Code ou pelo PowerShell do próprio Windows.

  1. Ligue o PC e espere o Windows terminar de carregar. Não deixe o computador dormir durante a auditoria remota.
  2. Confira o Tailscale no PC. Perto do relógio do Windows, procure o ícone do Tailscale. Abra-o e confirme que está conectado. Se pedir login, entre na mesma conta usada no iPhone.
  3. Confira o MySQL. Ele está configurado para iniciar automaticamente neste PC. Se o aplicativo disser que não consegue conectar ao banco, pressione a tecla Windows, digite Serviços, abra o aplicativo Serviços, procure MySQL80 e confira se o estado é “Em execução”. Se estiver parado, clique com o botão direito em MySQL80 e escolha Iniciar.
  4. Escolha onde abrir o terminal.
    • Opção A — VS Code: abra a pasta C:\Users\Flávio\Documents\Projeto_Patrimonio_web no VS Code e escolha Terminal → Novo Terminal.
    • Opção B — PowerShell do Windows: abra o menu Iniciar, digite PowerShell e abra o aplicativo Windows PowerShell. Não é necessário abrir o VS Code.
    • Opção C — Prompt de Comando (CMD): abra o menu Iniciar, digite Prompt de Comando ou cmd e abra o aplicativo.
  5. Digite os comandos do terminal que escolheu. Escolha apenas um dos blocos abaixo; não misture comandos de PowerShell com comandos de CMD.

    PowerShell do Windows: copie cada linha e pressione Enter:

    $env:PATRIMONIO_STORAGE = "mysql"
Set-Location "C:\Users\Flávio\Documents\Projeto_Patrimonio_web"
.\.venv\Scripts\python.exe app.py

    Prompt de Comando (CMD): copie cada linha e pressione Enter:

    cd /d "C:\Users\Flávio\Documents\Projeto_Patrimonio_web"
set PATRIMONIO_STORAGE=mysql
.\.venv\Scripts\python.exe app.py

    Terminal do VS Code: se ele já estiver aberto na pasta do projeto, veja o nome do terminal. Se disser PowerShell, use o bloco PowerShell; se disser Command Prompt ou CMD, use o bloco CMD.

    Se o terminal já estiver na pasta, não precisa executar o comando que muda de pasta (PowerShell: Set-Location; CMD: cd /d).
  6. Digite a senha MySQL do aplicativo quando for solicitada. A senha não aparecerá enquanto você digita; isso é normal. Pressione Enter depois de digitá-la. Não cole nem compartilhe a senha em mensagens ou arquivos.
  7. Deixe o terminal e o PC ligados. O sistema está iniciado quando o terminal mostra os endereços de acesso e não voltou para a linha de comando. Não feche a janela do terminal e não pressione Ctrl+C enquanto estiver usando o sistema. Você pode minimizar a janela.
  8. No iPhone, ligue o Tailscale e confirme que está conectado. Abra o Safari e digite http://100.85.183.31:8765. Este é o endereço atual confirmado para este PC; se algum dia não funcionar, confira o endereço do PC em Máquinas no painel Tailscale.
Resumo fácil de lembrar Depois de reiniciar o PC: Tailscale conectado + MySQL em execução + Flask iniciado no terminal (VS Code, PowerShell ou CMD) + Tailscale ligado no iPhone. O IP Tailscale normalmente não muda; o servidor Flask é que precisa ser iniciado novamente.

Para desligar o servidor de forma normal, volte à mesma janela do terminal e pressione Ctrl+C. Isso encerra o Flask, mas não apaga os dados. Se desligar ou reiniciar o Windows sem esse passo, o Flask também para e precisará ser iniciado novamente na próxima vez.

4. Preparar ou atualizar a base

  1. Exporte do SH3 o cadastro patrimonial no formato CSV e escolha Validar e importar CSV. A validação ocorre antes de substituir o arquivo atual. Se já existir uma fonte, confirme a substituição somente se o arquivo novo for o correto.
  2. Quando disponíveis, importe as planilhas Excel de bens alienados e bens baixados. A planilha de baixados precisa ter uma coluna chamada Plaqueta. Essas planilhas são auxiliares; o cadastro CSV continua sendo a base patrimonial.
  3. Clique em Preparar Dados (SH3). A rotina cruza as plaquetas, atualiza a conferência e informa totais e avisos. A lista de baixados marca como BAIXA os bens encontrados; se um item também estiver na lista de alienados, prevalece ALIEN.
  4. Confira os avisos e o painel de situação antes de iniciar a auditoria.

Uma preparação pode reorganizar os registros com os dados mais recentes das fontes. Faça um backup e evite executá-la enquanto outras pessoas estiverem alterando itens.

5. Auditar por setor

  1. Escolha o setor no campo Conferência por setor e clique em Iniciar.
  2. Revise a identificação e os dados exibidos. Abra Editar para registrar status, estado de conservação e observação.
  3. Salve a conferência. Para trocar ou anexar uma foto, selecione a imagem e use Salvar foto e alterações; esse comando também salva status, estado, observação e, quando permitido, descrição.
  4. Se encontrar um bem físico ainda não cadastrado e sem plaqueta, clique em Incluir bem localizado sem plaqueta, informe setor, descrição, quantidade, estado e observação. O sistema gera um identificador provisório individual; ele não cria uma plaqueta oficial.

As descrições de registros patrimoniais importados não são editáveis. Registros manuais sem plaqueta podem ter descrição corrigida; registros oriundos de planilhas auxiliares preservam a descrição de origem.

O servidor atende uma solicitação por vez. Evite que duas pessoas editem o mesmo item simultaneamente e aguarde a mensagem de confirmação antes de fechar a página.

6. Pesquisar e filtrar

Na Busca geral de bens, os filtros podem ser combinados:

  • Texto: procura em campos do registro, como código, plaqueta, descrição e observação.
  • Setores: selecione um ou mais; em uma lista múltipla, use Ctrl (Windows) ou toque conforme o navegador para selecionar várias opções.
  • Status: permite selecionar um ou mais status.
  • Plaqueta: escolha Todas, Com plaqueta ou Sem plaqueta. Para localizar itens sem identificação numérica, escolha Sem plaqueta.
  • Foto: filtra itens com ou sem referência de imagem.
  • Período: limita pelos campos de data disponíveis.

Clique em Buscar para pesquisar pelo texto. Os filtros Plaqueta e Foto são aplicados automaticamente quando alterados. Use Limpar filtros para apagar os critérios e pesquisar sem restrições. Os botões de relatório exportam os resultados encontrados, respeitando os filtros atuais.

O relatório gerencial é diferente: ele resume toda a base, não apenas os resultados da Busca Geral.

7. Entender os status

Os status registram a classificação da conferência. A convenção final deve seguir o procedimento patrimonial do órgão.

StatusUso no sistema
PENDAguardando conferência.
OKConferido sem divergência registrada.
DIVERGHá divergência ou pendência a verificar; pode incluir bem localizado sem plaqueta.
N_LOCBem não localizado na conferência.
SEM_PLAQClassificação disponível para item sem plaqueta.
NAO_EMPLACClassificação disponível para item não emplacado.
ALIENBem marcado como alienado pela fonte auxiliar.
BAIXABem marcado como baixado pela fonte auxiliar.

Um registro sem plaqueta não necessariamente está com status SEM_PLAQ. Alguns achados ficam como DIVERG e trazem a observação “ITEM LOCALIZADO SEM PLAQUETA - PENDENTE DE CADASTRO”. Por isso, use o filtro próprio Plaqueta → Sem plaqueta para encontrar todos, independentemente do status. Para N_LOC e BAIXA, o sistema define o estado como NAO_APLICAVEL.

8. Fotos dos bens

As imagens são anexadas individualmente pela edição de cada bem. O sistema não oferece importação de fotos em ZIP. Formatos permitidos e limites são validados pelo aplicativo antes de gravar.

As miniaturas aparecem nas tabelas quando existe um arquivo associado. Clique na miniatura para abrir a imagem. Se a referência constar no registro mas o arquivo não estiver no servidor, a tela indica que a foto está indisponível; anexe novamente a imagem correta ao bem correspondente.

9. Relatórios

  • Relatório de pendências: gera uma planilha gerencial com resumo geral, resumo por setor, detalhamento completo e abas específicas de conferidos, baixados, pendências, divergências, localizados sem plaqueta e não localizados.
  • Relatórios da Busca Geral: exportam a seleção atual em Excel ou PDF, com os filtros aplicados.

Os relatórios gerados ficam na pasta de relatórios do servidor. Baixe-os pela própria interface quando precisar guardar uma cópia fora do PC.

10. Backup e restauração

  1. Em Backup e restauração, clique em Criar backup agora. O ZIP reúne as entradas, planilhas de trabalho, fotos disponíveis, backups e relatórios desta versão web.
  2. Baixe o ZIP para um local seguro, separado do computador servidor. Um backup armazenado somente no próprio PC não protege contra falha ou perda desse computador.
  3. Para recuperar, selecione Restaurar no backup desejado e confirme. A aplicação cria outro backup do estado atual antes de substituir os dados web.

Somente backups ZIP criados por esta versão web são compatíveis. O ZIP guarda os arquivos de entrada, as planilhas e fotos de trabalho e os relatórios; os outros ZIPs de backup não são recopiados dentro dele. No modo MySQL, a restauração também sincroniza a tabela ativa com a planilha restaurada. Não extraia um backup por cima das pastas enquanto o sistema estiver em uso.

11. Onde ficam os dados

  • dados_web\dados_entrada: CSV patrimonial e arquivos auxiliares importados.
  • dados_web\dados_trabalho: planilhas de conferência, histórico, versões e pasta Fotos.
  • dados_web\relatorios: relatórios gerados.
  • dados_web\backups: backups ZIP da aplicação web.
  • MySQL local: banco patrimonio_web, tabela patrimonio_itens.

Esses dados são independentes da pasta do aplicativo desktop. A primeira execução não importa arquivos do desktop automaticamente.

12. Problemas comuns

  • A página não abre: confirme que o PC não suspendeu, que o serviço MySQL está ativo, que o terminal do Flask continua aberto e que o endereço inclui :8765.
  • Acesso remoto falha: confirme que os dois dispositivos aparecem conectados no Tailscale e use o IP Tailscale do PC servidor. Endereço local como 192.168.x.x pode não funcionar fora da rede doméstica.
  • O painel diz que não há dados: confira no painel se a fonte está importada e se o MySQL está ativo. Não reimporte nem prepare dados para tentar corrigir sem primeiro verificar a fonte correta.
  • Consulta pela extensão Database falha: a extensão Database do VS Code é separada do Flask. Se aparecer “No database selected”, selecione o schema patrimonio_web ou qualifique a tabela; isso não significa necessariamente que o site caiu.
  • Fotos indisponíveis: o banco pode manter o nome da referência sem o arquivo de imagem. Reanexe a imagem original ao bem certo; não associe arquivos por tentativa.

13. Segurança e boas práticas

  • Restrinja a rede Tailscale a dispositivos e usuários autorizados: dentro do app, todos têm poder de edição, importação, restauração e download.
  • Não compartilhe o endereço Tailscale publicamente, não encaminhe a porta do app no roteador e não use o serviço em uma rede pública aberta.
  • Crie backups antes de operações importantes e mantenha uma cópia baixada fora do PC servidor.
  • Evite alterações simultâneas no mesmo item. Aguarde a confirmação após cada salvamento.
  • Não execute testes automatizados apontando para a pasta de dados operacional. A suíte deve usar seu diretório temporário de testes.
  • CSV, planilhas, fotos e relatórios contêm informações patrimoniais: armazene e compartilhe apenas em locais autorizados.
